# Model Artifacts

This folder stores small deployable reference weights that are safe to keep in
the private repository.

These files are examples for the bundled reference task. They are not the whole
VantaLane model registry and they should not be treated as a limit on what the
toolflow can inspect.

## Tracked Reference Weights

- `current_2class_yolo26s_seg_best.pt`
  - Reference YOLO26 segmentation model.
  - Detects two geometric classes: `bottle` and generic `manual`.
  - The local service can then use OCR to map manual crops into text-specific
    business classes.

- `current_5class_yolo26s_seg_best.pt`
  - Reference YOLO26 segmentation model trained for the original five
    accessories: bottle plus four manual types.
  - Useful for comparing direct YOLO classification against the YOLO + OCR
    reference flow.

## Task-Trained Models

New task models are generated by the local service and are normally stored under:

```text
local_inspection_service/data/outputs/training_runs/<task_id>/
```

Each task-trained run should carry metadata that identifies:

- task id,
- selected accessory ids,
- required accessory counts,
- YOLO class-to-accessory mapping,
- model variant (`yolo` or `yolo_ocr`),
- artifact path,
- OCR accessory ids where relevant.

Those generated runs are intentionally not committed to Git. Keep only small,
stable reference weights here when they are needed for development or demo use.

## Not Tracked

- Full training datasets.
- Full YOLO run folders.
- Intermediate checkpoints.
- Temporary or experimental task models.
- Uploaded media and local service outputs.

Large artifacts remain in the local workspace and are reproduced through the
service UI or tracked scripts.
